### 4. 인증 정책

| No. | 정의 항목 | 합의 내용 |
| --- | --- | --- |
| 4-1 | 인증 방식 | JWT (JSON Web Token) |
| 4-2 | Access Token 방식 | Stateless Bearer Token — `Authorization: Bearer {accessToken}` 헤더로 전달 |
| 4-3 | Access Token 만료 시간 | 30분 |
| 4-4 | Refresh Token 방식 | HttpOnly Cookie로 전달 (XSS 방어) — `/api/member/token/refresh` 로 재발급 |
| 4-5 | Refresh Token 만료 시간 | 1주일 |
| 4-6 | Token 저장 위치 | Access Token: 브라우저 메모리 (LocalStorage 금지) / Refresh Token: HttpOnly Cookie |
| 4-7 | 로그아웃 처리 | 서버 측 Refresh Token 무효화 + 브라우저 메모리에서 Access Token 제거 |
| 4-8 | 세션 만료 처리 | Access Token 만료 시 Refresh Token으로 자동 재발급 시도, Refresh Token도 만료 시 로그인 페이지로 리다이렉트 |
| 4-9 | 비인증 접근 허용 범위 | 상품·장인 목록/상세 조회, 챗봇, 장바구니(게스트), 로그인·회원가입 |
| 4-10 | OAuth 소셜 로그인 | 카카오 / 구글 OAuth2 — 최초 로그인 시 추가 정보 입력 후 `USER` role 부여 |
| 4-11 | ARTISAN role 전환 | 장인 가입 신청(`POST /api/member/artisans/applications`) → ADMIN 승인 후 role 전환 |

### 6. 인증 실패 및 예외 처리

| No. | 상황 | HTTP Status | errorCode | 처리 기준 |
| --- | --- | --- | --- | --- |
| 6-1 | 미인증 사용자의 인증 필요 API 접근 | `401` | `UNAUTHORIZED` | 로그인 페이지로 리다이렉트 |
| 6-2 | Access Token 만료 | `401` | `UNAUTHORIZED` | FE가 Refresh Token으로 자동 재발급 요청 후 원래 요청 재시도 |
| 6-3 | Refresh Token 만료 | `401` | `UNAUTHORIZED` | 로그인 페이지로 리다이렉트, 브라우저 토큰 전체 제거 |
| 6-4 | 권한 없는 API 접근 (role 불일치) | `403` | `FORBIDDEN` | 접근 거부 응답 반환, 리다이렉트 없음 |
| 6-5 | 잘못된 인증 정보 (위조·변조 토큰) | `401` | `UNAUTHORIZED` | 토큰 무효화 후 로그인 페이지로 리다이렉트 |
| 6-6 | 로그아웃 상태에서 인증 API 요청 | `401` | `UNAUTHORIZED` | 로그인 페이지로 리다이렉트 |
| 6-7 | 이메일 미인증 계정 로그인 시도 | `403` | `FORBIDDEN` | 인증 이메일 재전송 안내 |
