## 유스케이스 통합 시나리오 (Use Case)

> Flow별 핵심 성공 경로와 경계 조건. 개별 도메인 시나리오는 아래 섹션 참고.

### Flow 1 — 목적 분명: 검색·필터 직접 구매 (기존 회원)

- _로그인 후 GNB 검색에 키워드를 입력하면 `GET /api/products?keyword=` 결과가 반환된다._
- _대분류·소분류 카테고리를 선택하면 `GET /api/products?category=&subcategory=` 필터가 적용된 목록이 반환된다._
- _가격대·소재·선물테마·컬러·종목 필터를 복합 적용하면 조건에 맞는 상품만 반환된다._
- _필수 옵션 미선택 상태에서 「구매하기」를 클릭하면 주문 생성이 차단된다._
- _주문 생성(`POST /api/payments/orders`) 시 재고와 가격이 최종 검증되어 재고 부족이면 BUSINESS_RULE_VIOLATION이 반환된다._
- _결제 준비(`POST /api/payments`) 후 승인(`POST /api/payments/confirm`) 없이 이탈하면 주문 상태가 PAID로 전환되지 않는다._
- _결제 승인 완료 시 주문번호가 생성되고 주문 상태가 PAID로 변경된다._

### Flow 2 — 목적 불분명: AI 추천 챗봇 탐색 구매 (신규 회원)

- _회원가입(`POST /api/member/signup`) 직후 이메일 인증 전에는 로그인이 거부된다(403)._
- _챗봇 세션 생성(`POST /api/chatbot/sessions`) 후 자연어 메시지를 전송하면 추천 상품 최대 3개와 reply가 반환된다._
- _AI 서버 응답 실패 시 챗봇은 500이 아닌 200과 fallback 메시지를 반환한다._
- _찜 등록(`POST /api/products/{productId}/wish`) 후 찜 목록(`GET /api/member/me/wishes`)에 해당 상품이 포함된다._
- _동일 상품을 중복 찜해도 DB에 1건만 저장된다(UNIQUE 제약)._
- _장바구니에 담긴 상품으로 주문 생성 시 배송지가 자동으로 기본 배송지로 채워진다._
- _회원가입 시 입력한 이메일로 인증 메일이 자동 발송된다._

### Flow 3 — 반품·환불 요청: 주문 이력·배송 추적 → 반품 신청 (기존 회원)

- _마이페이지 주문 목록(`GET /api/member/me/orders`)에서 결제 완료 주문이 조회된다._
- _주문 상세(`GET /api/member/me/orders/{orderId}`)에서 배송 단계 인디케이터가 정확히 반영된다._
- _배송 조회(`GET /api/payments/orders/{orderId}/delivery`)에서 택배사·송장번호·배송 단계가 반환된다._
- _반품 신청(`POST /api/payments/returns`) 요청 시 주문 상태가 RETURN_REQUESTED로 변경되고 장인·관리자에게 알림이 전송된다._
- _반품 사유가 DEFECTIVE(파손·불량)인 경우 imageIds 미제출 시 INVALID_INPUT이 반환된다._
- _반품 불가 기간이 지난 주문의 반품 신청 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _이미 반품 접수된 주문에 재신청 시 CONFLICT가 반환된다._
- _존재하지 않는 orderId 또는 returnAddressId로 반품 신청 시 NOT_FOUND가 반환된다._

## 회원 (member)

- _이미 가입된 이메일로 회원가입 시 CONFLICT 에러가 반환된다._
- id,pw 회원가입 방식에서 이메일 인증은 메일로 인증 허용 링크가 제공된다.
- URL에 memberId/email 같은 식별 가능한 개인정보가 직접 노출되지 않는다.
- 충분한 entropy를 가진 일회성 opaque token을 사용한다.
- 이메일 가입 방식의 허용된 링크는 1회성 허용 링크이다.
- 허용된 링크는 15동안 지속되면 이후 허용되지 않는 방식으로 변경된다. 
- 한명의 유저에게 허용된 링크는 가장 마지막에 인증요청한 링크이며 가장 먼저 요청한 링크가 15분이 지나지 않았더라도 가장 최근에 (즉마지막에) 보낸것 이 아니라면 허용되지 않는 링크가 된다.
- 이메일 인증 완료 후 동일 인증 링크를 재사용해도 회원 상태가 추가로 변경되지 않는다.
- _이메일 인증 미완료 계정은 로그인 시 FORBIDDEN이 반환된다._
- _카카오/구글 최초 로그인 시 추가정보 입력 없이 서비스 이용 불가._
- _로그아웃 후 기존 Refresh Token은 서버에서 무효화되어 재사용 불가._
- _회원 탈퇴 시 소프트 딜리트(WITHDRAWN) 처리되며 동일 이메일 재가입은 정책에 따른다._
- _배송지는 기본 배송지를 1개만 가질 수 있다._
- 기본 배송지가 이미 존재하는 상태에서 다른 배송지를 기본 배송지로 변경하면 기존 기본 배송지는 false로 변경되고 새로운 배송지만 default=true가 된다.
- _찜 목록은 본인만 조회 가능하다._
- _최근 본 상품은 게스트(쿠키)와 로그인 회원 양쪽에서 기록되며, 로그인 시 병합된다._
- _장인 신작 알림 구독은 USER 역할을 가져야 가능하다._
- _위변조되거나 만료된 JWT로 요청 시 401이 반환되고 내부 처리를 수행하지 않는다._
- _USER 권한 토큰으로 ADMIN 전용 엔드포인트 호출 시 FORBIDDEN이 반환된다(권한 상승 차단)._
- _로그인 실패가 단시간에 반복될 경우 rate limit에 의해 추가 시도가 차단된다._
- 만료된 이메일 인증 토큰으로 인증 요청 시 INVALID_TOKEN 또는 FORBIDDEN이 반환된다.
- A 회원에게 발급된 이메일 인증 토큰으로 B 회원의 인증 상태를 변경할 수 없다.

## 상품 (products)

### 상품 상태 머신

| 현재 상태 | 이벤트 | 다음 상태 |
|-----------|--------|-----------|
| `DRAFT` | publish (콘텐츠 승인 후 게시) | `ON_SALE` |
| `ON_SALE` | stock=0 (재고 소진) | `SOLD_OUT` |
| `SOLD_OUT` | restock (재입고) | `ON_SALE` |
| `ON_SALE` | hide | `HIDDEN` |
| `HIDDEN` | restore | `ON_SALE` |

_DRAFT → ON_SALE publish 전환 시 상품이 공개 목록에 노출된다._
_ON_SALE 상태에서 재고를 0으로 설정하면 상태가 SOLD_OUT으로 자동 전환된다._
_SOLD_OUT 상태에서 재고를 1 이상으로 업데이트하면 상태가 ON_SALE로 복원된다._
_ON_SALE 상태에서 hide 요청 시 상태가 HIDDEN으로 전환되고 공개 목록에서 제거된다._
_HIDDEN 상태에서 restore 요청 시 상태가 ON_SALE로 복원된다._
_DRAFT → SOLD_OUT 직접 전환은 허용되지 않으며 BUSINESS_RULE_VIOLATION이 반환된다._
_DRAFT → HIDDEN 직접 전환은 허용되지 않으며 BUSINESS_RULE_VIOLATION이 반환된다._
_SOLD_OUT 상태에서 hide 요청 시 BUSINESS_RULE_VIOLATION이 반환된다(HIDDEN으로 직접 전환 불가)._
_HIDDEN 상태 상품에 publish 요청 시 BUSINESS_RULE_VIOLATION이 반환된다(DRAFT를 거쳐야 함)._

- _ARTISAN만 상품을 등록·수정·삭제할 수 있다._
- _본인이 등록하지 않은 상품은 수정·삭제 시 FORBIDDEN이 반환된다._
- _DRAFT 상태 상품은 소비자 목록·상세 조회에 노출되지 않는다._
- _재고가 0인 상품은 SOLD_OUT으로 자동 전환된다._
- _상품 문의 비밀글은 작성자와 해당 ARTISAN만 내용을 볼 수 있다._
- _상품 후기는 해당 주문 상품(order_item)에 대해 1회만 작성 가능하다._
- 찜 등록과 취소는 USER 역할이 포함되어야만 가능하다.
- _ARTISAN role은 내부적으로 USER를 포함하므로 장인도 찜 등록·조회가 가능하다._
- _상품 목록은 cursor 기반 페이지네이션으로 반환되며 nextCursor가 null이면 마지막 페이지다._
- 동일 조건으로 cursor 페이지를 연속 조회하면 이전 페이지와 다음 페이지 사이에 동일 productId가 중복 반환되지 않는다.
- 마지막 cursor 이후 요청 결과는 빈 items와 nextCursor=null을 반환한다.
- 변조된 cursor를 전달하면 INVALID_INPUT이 반환된다.
- _카테고리·소재 목록은 Public 엔드포인트로 인증 없이 조회 가능하다._
- _DRAFT·HIDDEN 상태 상품을 공개 상세 조회(GET /api/products/{productId})하면 404가 반환된다._
    - 공개 상태와 비공개 상태 가 정상적으로 동작 되어야 한다.
- _상품 등록 직후 상태는 항상 DRAFT이며, 콘텐츠 게시(publish) 전까지 ON_SALE로 전환되지 않는다._
- _동일 회원이 같은 상품을 중복 찜해도 DB에 (member_id, product_id) 조합의 레코드가 2건 생기지 않는다._
- _재고 차감은 조건부 원자적 UPDATE(stock >= 요청수량)로 수행되어 재고가 음수가 되지 않는다._
- _장인 본인 상품이 아닌 문의에 답변 시 FORBIDDEN이 반환된다._
- _상품 목록 조회 시 sort 파라미터를 생략하면 POPULAR(인기순)로 정렬된 결과가 반환된다._
    - 정렬 타입마다 값을 기준으로 테스트 필수요구
- _sort=NEWEST 로 조회하면 created_at 내림차순으로 정렬된 결과가 반환된다._
- _sort=WISHLIST_COUNT 로 조회하면 찜 수 내림차순으로 정렬된 결과가 반환된다._
- _sort=SALES_COUNT 로 조회하면 판매 수 내림차순으로 정렬된 결과가 반환된다._
- _sort=PRICE_ASC 로 조회하면 가격 오름차순으로 정렬된 결과가 반환된다._
- _sort=PRICE_DESC 로 조회하면 가격 내림차순으로 정렬된 결과가 반환된다._
- _SOLD_OUT 상태 상품은 공개 목록·상세 조회에 노출되지만 주문 생성 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _excludeSoldOut 파라미터를 생략하면 품절 상품이 제외된 목록이 반환된다(기본값 true)._
- _maxPrice < minPrice 조건으로 조회 시 INVALID_INPUT이 반환된다._
- _hasGiftWrap=true 필터를 적용하면 선물 포장 가능한 상품만 반환된다._
- _subcategory 파라미터는 category 없이 단독으로 사용 가능하며 해당 세부 품목 상품만 반환된다._
- _category와 해당 category 소속이 아닌 subcategory 조합으로 조회하면 items가 빈 배열로 반환된다._
- 재고가 1개인 상품에 대해 서로 다른 두 사용자가 동시에 1개씩 주문하면 하나의 주문만 성공하며, 다른 요청은 BUSINESS_RULE_VIOLATION이 반환되고 최종 stock은 0이다.
- 정렬 기준 값이 동일한 상품은 productId 등의 고정된 2차 정렬 기준으로 항상 동일한 순서를 유지한다.

## 결제 (payments)

- _장바구니는 게스트(guest_cart_id 쿠키)와 로그인 회원 양쪽을 지원하며 로그인 시 병합된다._
- _재고가 부족한 상품을 주문 생성 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _결제 준비 후 토스페이먼츠 승인 전 이탈 시 결제 실패로 처리된다._
- _결제 승인(confirm) 없이 주문은 PAID 상태가 되지 않는다._
- _이미 취소된 결제를 재취소 시 CONFLICT가 반환된다._
- _USER 역할만 주문을 생성할 수 있다._
- _타인의 orderId로 주문 상세 조회 시 FORBIDDEN이 반환된다(IDOR 차단)._
- _주문 생성 시 클라이언트가 전달한 가격이 아닌 서버가 DB에서 조회한 상품 가격으로 결제 금액이 산정된다(price 조작 차단)._
- _토스페이먼츠 웹훅 요청의 서명(Authorization 또는 HMAC)이 유효하지 않으면 FORBIDDEN을 반환하고 내부 처리를 수행하지 않는다._
- 결제 준비 후 승인(confirm)이 수행되지 않은 주문은 PAID 상태로 변경되지 않는다.

### 결제 Webhook 멱등성

_동일 paymentKey와 PAYMENT_DONE 이벤트가 포함된 웹훅이 두 번 전달되더라도 결제 레코드는 1건, 주문 상태 전환은 1회, 재고 차감은 1회, 발송 알림은 1회만 수행된다._
_웹훅 1차 처리 완료 후 동일 웹훅 재전송 시 200을 반환하되 내부 상태 변경 없이 종료된다(멱등 키: paymentKey + eventType)._
_PAYMENT_DONE 웹훅이 중복 수신된 시점에 이미 PAID 상태인 주문은 상태 변경 없이 그대로 유지된다._
_PAYMENT_FAILED 웹훅이 중복 수신된 경우에도 PAYMENT_FAILED 상태로의 전환은 1회만 수행된다._

## 알림 (notifications)

- _알림은 본인 것만 조회 가능하다._
- _읽지 않은 알림 수는 실시간 카운트를 반환한다._
- _존재하지 않는 알림 ID로 읽음 처리 시 NOT_FOUND가 반환된다._
- _전체 읽음 처리 후 unread-count는 0이 된다._
- _알림 수신 설정을 끈 회원에게는 해당 이벤트 알림이 발송되지 않는다._
- _동일 이벤트가 Redis Stream에 중복 소비되더라도 알림 row는 1건만 생성된다(events.stream_message_id UNIQUE 멱등성)._
- _동일 이벤트에 대해 동일 회원에게 알림이 두 번 발송되지 않는다(notifications UNIQUE(event_id, member_id) 멱등성)._
- _SSE 연결 중인 회원에게 알림 발송 시 실시간으로 수신된다._
- _SSE 연결이 끊겼다 재연결 시 Last-Event-ID 이후 누락된 알림이 재전송된다._
- _SSE 연결 없이 발생한 알림은 목록 조회 API로 확인 가능하다._
- _Redis Stream 소비 중 인스턴스 장애 발생 시 PEL에 남은 미확인 메시지가 재클레임되어 재처리된다._
- _PEL(1,3,5,10 (분)) 재시도가 모두 소진된 이벤트는 PERMANENTLY_FAILED 상태로 전환되고 이후 재처리되지 않는다._
- _팬아웃 대상이 대량이어도 알림 INSERT는 chunkSize 단위 배치로 처리되어 단건 반복 INSERT가 발생하지 않는다._
- _알림 설정 캐시(Redis)가 만료된 경우 DB에서 재조회 후 캐시를 채우고 정상 발송된다._
- _spring.mvc.async.request-timeout이 -1(무제한)로 설정되지 않으면 Tomcat 기본값(30s)에 의해 SSE 연결이 첫 heartbeat 직후 종료된다._
- _SseEmitter가 timeout=-1(무제한)로 생성되지 않으면 Tomcat async 타임아웃 설정에 따라 연결이 조기 종료된다._
- _30초 간격 heartbeat ping 이벤트가 전송되어 nginx proxy_read_timeout 및 ALB idle timeout에 의한 연결 강제 종료를 방지한다._
- _Redis sse:online:{memberId} TTL(90s)이 heartbeat 간격(30s)보다 짧게 설정되면 연결 중에도 온라인 상태가 만료되어 멀티 인스턴스 브로드캐스트 라우팅이 실패한다._
- _heartbeat 전송마다 Redis sse:online:{memberId} TTL이 갱신되어 연결이 유지되는 동안 온라인 상태가 만료되지 않는다._
- _ALB idle timeout이 heartbeat 간격(30s)보다 짧게 설정된 EC2 환경에서는 SSE 연결이 조기 종료된다._

## 관리자 (admin)

- _ADMIN 역할이 아닌 사용자가 장인 승인 API 호출 시 FORBIDDEN이 반환된다._
- _이미 승인된 신청을 재승인 시 CONFLICT가 반환된다._
- _승인 시 해당 회원의 role이 USER → ARTISAN으로 변경된다._
- _반려 시 reject_reason은 필수 입력이다._

## 컨텐츠 (content)

- _AI 상세페이지 생성 요청 시 이미지를 3장 미만 또는 12장 초과로 전달하면 INVALID_INPUT이 반환된다._
- _취재 데이터(making_story, usage_care) 없이 AI 상세페이지 생성 요청 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _AI 생성 상태가 PROCESSING일 때 폴링은 동일 generationId로 반복 조회한다._
- _FAILED 상태에서 재생성 요청은 동일 엔드포인트(POST generations) 재호출로 처리된다._
- _콘텐츠 승인 후 게시(publish) 시 AI파트로 상품 데이터가 동기화된다._
- _콘텐츠 반려 후 수정 없이 게시 요청 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _본인 상품이 아닌 콘텐츠 수정 시 FORBIDDEN이 반환된다._
- _버전 조회는 이전 생성 결과 이력을 모두 반환한다._
- _factCheckConfirmed 또는 photoMatchConfirmed 중 하나라도 false이면 승인 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _APPROVED 상태가 아닌 콘텐츠를 게시(publish) 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _콘텐츠 반려(reject) 시 rejectReason 없이 요청하면 INVALID_INPUT이 반환된다._
- _동일 콘텐츠에 승인과 반려가 동시 요청되면 한쪽은 409 CONCURRENT_UPDATE가 반환되고 content.version이 단 한 번만 증가한다(낙관적 락 CONC-006)._
- _PENDING_REVIEW 상태가 아닌 콘텐츠에 승인·반려 요청 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _콘텐츠 블록은 h2·p·img·video 태그 중 하나이며 그 외 tag 값은 INVALID_INPUT이 반환된다._
- _detailPageBlocks[].imageVariants가 null인 블록(h2·p·video)에 이미지 URL을 삽입할 수 없다._
- AI 생성 콘텐츠에 script 태그가 포함되면 저장 또는 게시가 거부된다.
- 허용 태그의 이벤트 핸들러 속성(onerror, onclick 등)은 제거 또는 거부된다.
- javascript: scheme URL은 콘텐츠에 저장할 수 없다.
- iframe·object·embed 등 허용되지 않은 콘텐츠는 게시할 수 없다.
- AI 서버가 허용되지 않은 tag 또는 attribute를 반환해도 BE validation을 통과할 수 없다.

## 이미지 (images)

- _Presigned URL 발급 후 업로드하지 않은 이미지는 consumed=false 상태로 주기적으로 정리된다._
- _다른 회원의 이미지 삭제 시 FORBIDDEN이 반환된다._
- _이미지 소유권 검증(internal/images/verify)은 내부 서비스 간 통신 전용으로 외부에서 직접 호출 시 FORBIDDEN이 반환된다._
- _만료된 Presigned URL로 S3 업로드를 시도하면 업로드가 거부된다._
- _Presigned URL 발급 시 허용 Content-Type 외 파일 타입 업로드 시도는 차단된다._
- _프론트에서 320·640·1280px WebP로 변환한 3개 파일을 각각 Presigned URL로 S3에 업로드한 뒤 imageId 하나를 백엔드에 전달하면, 백엔드는 image_upload.variants에서 3개 objectKey를 조합해 variants[] 형태로 API 응답에 반환한다._
- _imageId에 해당하는 variants가 320·640·1280w 중 하나라도 누락된 경우 해당 이미지를 상품에 연결하면 INVALID_INPUT이 반환된다._
- _variants가 모두 업로드된 imageId를 상품에 연결하면 product_image 레코드가 생성되고 consumed=true로 전환된다._
- 허용된 최대 파일 크기를 초과한 이미지 업로드는 거부된다.

### 상품 이미지 variants 구조 검증

- _상품 상세 조회 응답의 images[] 각 항목은 imageId·alt·variants 3개 필드를 모두 포함한다._
- _images[].variants 배열은 320w·640w·1280w 3개 항목을 포함하며 각 항목은 url·width·height·format(webp)을 모두 포함한다._
- _images[].variants[].height 값은 round(variantWidth / sourceWidth * sourceHeight) 공식으로 산출된다 (image_upload.source_width, source_height 기반)._
- _images[] 배열은 display_order 오름차순으로 정렬되어 반환된다._
- _동일 imageId로 두 상품에 연결 시도하면 두 번째 요청에서 CONCURRENT_UPDATE(409)가 반환된다 (CONC-007 consumed 원자적 소비)._
- _목록 응답의 thumbnail은 display_order=0 이미지의 variants 배열(320w·640w·1280w)과 일치한다._
- _thumbnail 배열의 각 항목은 url·width·height·format 4개 필드를 모두 포함한다._
- _상품 상세 응답의 detailPageBlocks[].imageVariants는 tag=img인 블록에만 값이 있고 나머지는 null이다._
- _detailPageBlocks[].imageVariants에는 320w·640w·1280w 3개의 WebP URL이 모두 포함된다._
- _동일 imageId를 consumed=false 상태에서 DELETE 후 상품에 연결 시도하면 NOT_FOUND가 반환된다._

## 챗봇 (chatbot)

- _챗봇 세션은 게스트와 로그인 회원 모두 생성 가능하다._
- _존재하지 않는 sessionId로 메시지 전송 시 NOT_FOUND가 반환된다._
- _AI 서버 응답 실패 시 BE가 Fallback 메시지를 반환하며 500이 아닌 200으로 응답한다._
- _AI 서버가 지정 timeout 내 응답하지 않아도 BE 요청이 무한 대기하지 않고 fallback 응답을 반환한다._
- _추천 결과가 없는 경우(products: []) reply는 항상 존재한다._
- _history는 최근 5~6턴만 전달되며 그 이상은 잘린다._
- _세션 종료 후 해당 sessionId로 메시지 전송 시 NOT_FOUND가 반환된다._
- _소비자 입력 원문은 BE에서 가공 없이 AI에 그대로 전달된다._
- _챗봇 응답의 suggestions는 AI가 생성한 후속 질문 제안으로 최대 3개이며, 추천 상품이 없어도 항상 포함된다._
- _gift_theme=COUPLE 필터로 상품 목록 조회 시 해당 테마 상품만 반환된다._
