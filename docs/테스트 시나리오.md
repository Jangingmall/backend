# 테스트 시나리오

#### 규칙

- **본 항목은 개발자가 직접 플랜을 짜며 AI 가 수정 및 삭제 는 하지 못하지만 추가는 가능하다**
- **AI 가 추가 할때는 아래오 같은 예시로 추가한다. (_) 기울기 추가**

  - ex) _유저는 복수계정을 소유할 수 없다._

---

## 회원 (member)

- _이미 가입된 이메일로 회원가입 시 CONFLICT 에러가 반환된다._
- _이메일 인증 미완료 계정은 로그인 시 FORBIDDEN이 반환된다._
- _카카오/구글 최초 로그인 시 추가정보 입력 없이 서비스 이용 불가._
- _로그아웃 후 기존 Refresh Token은 서버에서 무효화되어 재사용 불가._
- _회원 탈퇴 시 소프트 딜리트(deleted_at) 처리되며 동일 이메일 재가입은 정책에 따른다._
- _비밀번호 변경 후 기존 Access Token은 다음 만료 시까지 유효하다._
- _배송지는 기본 배송지를 1개만 가질 수 있다._
- _찜 목록은 본인만 조회 가능하다._
- _최근 본 상품은 게스트(쿠키)와 로그인 회원 양쪽에서 기록되며, 로그인 시 병합된다._
- _장인 신작 알림 구독은 USER 역할만 가능하다._

## 상품 (products)

- _ARTISAN만 상품을 등록·수정·삭제할 수 있다._
- _본인이 등록하지 않은 상품은 수정·삭제 시 FORBIDDEN이 반환된다._
- _DRAFT 상태 상품은 소비자 목록·상세 조회에 노출되지 않는다._
- _재고가 0인 상품은 SOLD_OUT으로 자동 전환된다._
- _상품 문의 비밀글은 작성자와 해당 ARTISAN만 내용을 볼 수 있다._
- _상품 후기는 해당 주문 상품(order_item)에 대해 1회만 작성 가능하다._
- _찜 등록과 취소는 USER 역할만 가능하다._
- _상품 목록은 cursor 기반 페이지네이션으로 반환되며 nextCursor가 null이면 마지막 페이지다._
- _카테고리·소재 목록은 Public 엔드포인트로 인증 없이 조회 가능하다._
- _DRAFT·HIDDEN 상태 상품을 공개 상세 조회(GET /api/products/{productId})하면 404가 반환된다._
- _상품 등록 직후 상태는 항상 DRAFT이며, 콘텐츠 게시(publish) 전까지 ON_SALE로 전환되지 않는다._
- _동일 회원이 같은 상품을 중복 찜해도 DB에 (member_id, product_id) 조합의 레코드가 2건 생기지 않는다._
- _재고 차감은 조건부 원자적 UPDATE(stock >= 요청수량)로 수행되어 재고가 음수가 되지 않는다._
- _장인 본인 상품이 아닌 문의에 답변 시 FORBIDDEN이 반환된다._
- _상품 목록 조회 시 sort 파라미터를 생략하면 POPULAR(인기순)로 정렬된 결과가 반환된다._
- _excludeSoldOut 파라미터를 생략하면 품절 상품이 제외된 목록이 반환된다(기본값 true)._
- _maxPrice < minPrice 조건으로 조회 시 INVALID_INPUT이 반환된다._

## 결제 (payments)

- _장바구니는 게스트(guest_cart_id 쿠키)와 로그인 회원 양쪽을 지원하며 로그인 시 병합된다._
- _재고가 부족한 상품을 주문 생성 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _결제 준비 후 토스페이먼츠 승인 전 이탈 시 결제 실패로 처리된다._
- _결제 승인(confirm) 없이 주문은 PAID 상태가 되지 않는다._
- _이미 취소된 결제를 재취소 시 CONFLICT가 반환된다._
- _환불 계좌는 가상계좌 환불 시에만 필수이며 미등록 시 환불 불가._
- _결제수단 등록 시 billing_key가 유효하지 않으면 등록 실패한다._
- _USER 역할만 주문을 생성할 수 있다._

## 알림 (notifications)

- _알림은 본인 것만 조회 가능하다._
- _읽지 않은 알림 수는 실시간 카운트를 반환한다._
- _존재하지 않는 알림 ID로 읽음 처리 시 NOT_FOUND가 반환된다._
- _전체 읽음 처리 후 unread-count는 0이 된다._
- _알림 수신 설정을 끈 회원에게는 해당 이벤트 알림이 발송되지 않는다._
- _동일 이벤트가 Redis Stream에 중복 소비되더라도 알림 row는 1건만 생성된다(events.stream_message_id UNIQUE 멱등성)._
- _동일 이벤트에 대해 동일 회원에게 알림이 두 번 발송되지 않는다(notifications UNIQUE(event_id, member_id) 멱등성)._
- _SSE 연결 중인 회원에게 알림 발송 시 실시간으로 수신된다._
- _SSE 연결이 끊겼다 재연결 시 Last-Event-ID 이후 누락된 알림이 재전송된다._
- _SSE 연결 없이 발생한 알림은 목록 조회 API로 확인 가능하다._
- _Redis Stream 소비 중 인스턴스 장애 발생 시 PEL에 남은 미확인 메시지가 재클레임되어 재처리된다._
- _PEL(1,3,5,10 (분)) 재시도가 모두 소진된 이벤트는 PERMANENTLY_FAILED 상태로 전환되고 이후 재처리되지 않는다._
- _팬아웃 대상이 대량이어도 알림 INSERT는 chunkSize 단위 배치로 처리되어 단건 반복 INSERT가 발생하지 않는다._
- _알림 설정 캐시(Redis)가 만료된 경우 DB에서 재조회 후 캐시를 채우고 정상 발송된다._

## 관리자 (admin)

- _ADMIN 역할이 아닌 사용자가 장인 승인 API 호출 시 FORBIDDEN이 반환된다._
- _이미 승인된 신청을 재승인 시 CONFLICT가 반환된다._
- _승인 시 해당 회원의 role이 USER → ARTISAN으로 변경된다._
- _반려 시 reject_reason은 필수 입력이다._

## 컨텐츠 (content)

- _취재 데이터(making_story, usage_care) 없이 AI 상세페이지 생성 요청 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _AI 생성 상태가 PROCESSING일 때 폴링은 동일 generationId로 반복 조회한다._
- _FAILED 상태에서 재생성 요청은 동일 엔드포인트(POST generations) 재호출로 처리된다._
- _콘텐츠 승인 후 게시(publish) 시 AI파트로 상품 데이터가 동기화된다._
- _콘텐츠 반려 후 수정 없이 게시 요청 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _본인 상품이 아닌 콘텐츠 수정 시 FORBIDDEN이 반환된다._
- _버전 조회는 이전 생성 결과 이력을 모두 반환한다._
- _factCheckConfirmed 또는 photoMatchConfirmed 중 하나라도 false이면 승인 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _APPROVED 상태가 아닌 콘텐츠를 게시(publish) 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _콘텐츠 반려(reject) 시 rejectReason 없이 요청하면 INVALID_INPUT이 반환된다._
- _동일 콘텐츠에 승인과 반려가 동시 요청되면 한쪽은 409 CONCURRENT_UPDATE가 반환되고 content.version이 단 한 번만 증가한다(낙관적 락 CONC-006)._
- _PENDING_REVIEW 상태가 아닌 콘텐츠에 승인·반려 요청 시 BUSINESS_RULE_VIOLATION이 반환된다._
- _콘텐츠 블록은 h2·p·img·video 태그 중 하나이며 그 외 tag 값은 INVALID_INPUT이 반환된다._

## 이미지 (images)

- _Presigned URL 발급 후 업로드하지 않은 이미지는 is_used=false 상태로 주기적으로 정리된다._
- _다른 회원의 이미지 삭제 시 FORBIDDEN이 반환된다._
- _이미지 소유권 검증(internal/images/verify)은 내부 서비스 간 통신 전용으로 외부에서 직접 호출 시 FORBIDDEN이 반환된다._

## 챗봇 (chatbot)

- _챗봇 세션은 게스트와 로그인 회원 모두 생성 가능하다._
- _존재하지 않는 sessionId로 메시지 전송 시 NOT_FOUND가 반환된다._
- _AI 서버 응답 실패 시 BE가 Fallback 메시지를 반환하며 500이 아닌 200으로 응답한다._
- _추천 결과가 없는 경우(products: []) reply는 항상 존재한다._
- _history는 최근 5~6턴만 전달되며 그 이상은 잘린다._
- _세션 종료 후 해당 sessionId로 메시지 전송 시 NOT_FOUND가 반환된다._
- _소비자 입력 원문은 BE에서 가공 없이 AI에 그대로 전달된다._
