# 장인몰 샘플 데이터 아키텍처 — 정렬·필터·AI추천 검증용

AI/FE/BE 3팀이 같은 데이터로 정렬·필터·추천을 눈으로 확인하기 위한 샘플 데이터 설계.

## 1. 목적별로 필요한 것이 다르다

| 팀 | 확인하고 싶은 것 | 데이터에 필요한 조건 |
| --- | --- | --- |
| FE | 필터 조합했을 때 결과가 실제로 줄어드는지, 정렬 버튼 누르면 순서가 바뀌는지 | 각 필터 축(종목/소재/컬러/가격대/불리언)마다 값이 **골고루 분포** — 몰리면 "필터링해도 다 나옴" 또는 "필터링하면 0건"이 되어 검증이 안 됨 |
| AI팀 | 추천이 그럴듯한지(엉뚱한 상품 안 나오는지) | `making_story`/`usage_care`가 **의미론적으로 실제 다른 이야기**여야 함 — 전부 비슷한 문장이면 벡터 유사도 테스트가 무의미 |
| BE | 정렬 API(`POPULAR`/`WISHLIST_COUNT`/`SALES_COUNT`/`PRICE_ASC` 등)가 값 기준으로 정확히 재배열되는지 | `popularity_score`/`wishlist_count`/`sales_count`/`price`가 **서로 다른 값으로 흩어져 있어야** 함(전부 0이거나 동률이면 정렬해도 티가 안 남) |

## 2. 데이터 모델 (3계층)

```
category (6종)
  └─ artisan_profile (52명, 종목별 8~9명씩 분산)
       └─ product (832개, 장인 1인당 평균 16개, 10~20개 범위로 변동)
```

## 3. 필터 축별 분포 설계

| 필터 축 | 값 종류 | 분포 전략 |
| --- | --- | --- |
| `category`(종목) | 6종 | 832개를 균등 분할(종목당 ~138개, METAL 150개) — 어느 종목으로 필터링해도 결과가 충분히 나오게 |
| `material`(소재) | 종목별 4~6종(도자기=청자·백자·분청·옹기토 등, 목공=느티나무·소나무·전통옻칠 등) | 종목 안에서만 의미 있는 조합으로 — "나전칠기인데 소재가 대나무"처럼 어색한 조합 방지 |
| `color` | 7종(화이트/블랙/그레이/레드/블루/그린/브라운) | 균등 분포하되, 종목 특성 반영(옹기는 브라운·블랙 비중 높게, 천연염색은 전 컬러 고르게) |
| `giftTheme` | 8종 + null(30%) | 전 상품에 강제 배정하지 않음 — 실제로도 모든 상품이 "선물용"은 아니므로 |
| `price` | 종목별 현실적 범위(다기류 3만~30만, 가구류 20만~200만) | 4구간(5만미만/5만~10만/10만~20만/20만이상) 확정 필터에 맞춰 각 구간에 실제 데이터가 존재하도록 |
| `isLimited`/`isCustomOrder`/`hasGiftWrap`/`isSingleItem` | boolean | 각각 15~30% 정도만 true — 전부 true/false면 필터 의미 없음 |
| `status` | ON_SALE 88% / SOLD_OUT 10% / DRAFT 1% / HIDDEN 1% | 품절 제외 토글, DRAFT 비노출 로직 테스트용 소수 포함 |

## 4. 정렬 축 분포 설계

| 정렬 기준 | 필드 | 분포 |
| --- | --- | --- |
| `PRICE_ASC`/`PRICE_DESC` | price | 위 가격 설계로 자연히 확보 |
| `WISHLIST_COUNT` | wishlist_count | 0~500 사이 지수분포(소수 인기상품만 매우 높게 — 실제 서비스와 유사한 롱테일) |
| `SALES_COUNT` | sales_count | 0~200 사이 지수분포, wishlist와 약한 상관관계(찜 많다고 다 팔리진 않음) |
| `POPULAR`(popularity_score) | popularity_score | wishlist_count·sales_count·최근성(is_new)을 가중합산한 값으로 **역산**해서 채움 — 실제 산식과 일치하는 샘플이 되도록 |
| `NEWEST` | created_at | 최근 14일 이내 12%(=`isNew` 배지와 연동), 나머지는 최근 1년에 분산 |

## 5. AI 추천 검증용 서사 데이터

- `making_story`(제작과정), `usage_care`(관리법)를 **종목별 템플릿 + 변수 조합**으로 생성하되, 다음 축이 실제로 구별되게:
  - **용도**(선물/다도/인테리어/실용) — `purposeTags`와 서사 내용을 일치시킴("선물용" 태그인데 서사는 "매일 쓰는 밥그릇" 이야기면 AI가 헷갈림
  - **격식도**(고급스러움/소박함) — `certification_level`(장인 등급)과 약하게 연동(보유자 작품 서사는 격식 있는 어휘, 이수자는 소박한 어휘)
- 챗봇 테스트 질의("환갑 선물, 고급스러운 걸로 5만원대") 같은 조건이 **실제로 몇 건은 걸리게** — 가격대×용도×격식도 조합이 최소 1건 이상 존재하도록 검산

## 6. 생성 방식

832개를 한 땀 한 땀 수작업하는 대신, **종목별 어휘 사전(품목명·소재·서사 조각)을 만들어 조합 생성** — 단, 무작위가 아니라 위 4·5장의 분포 전략을 강제하는 방식으로 시드값 고정 생성(재현 가능).
