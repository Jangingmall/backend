## 인프라 구성

### 서버 분리 구조

```
APP 티어 (EC2)
 └─ ALB → Spring Boot (내장 톰캣)
 └─ nginx: ALB 미도입 시 리버스 프록시로 대체 (현재 우선순위 낮음)

DB 티어 (EC2 또는 RDS)
 └─ PostgreSQL 18

Redis (EC2)
 └─ 세션/캐싱 용도 (기능 확정 전까지 선택적)

Monitoring (EC2)
 └─ Prometheus + Grafana
```

### ALB / nginx 결정

- **보안팀 WAF 적용 요건**으로 ALB 필요
- ALB 도입 시 nginx 불필요, ALB에서 TLS 종료
- ALB 비용: +$16~20/월 (nginx 대체 시 $0)
- **현재 방향: ALB 도입 (WAF 연동 고려)**

### DB 배치

- RDS 또는 EC2 직접 설치 모두 수용 가능
- 비용 절감 시 EC2 직접 설치 선택
- **결정 기준: 인프라팀 스냅샷 관리 여부 + 비용**

## 메트릭 / 모니터링

### Prometheus 엔드포인트

| 항목 | 값 |
|---|---|
| 엔드포인트 | `/actuator/prometheus` |
| 관리 포트 | `9090` |
| 헬스체크 | `/actuator/health` |
| liveness | `/actuator/health/liveness` |
| readiness | `/actuator/health/readiness` |
| 수집 주기 | 15s |

### application.yml 설정 (인프라 요구사항)

```yaml
server:
  shutdown: graceful

spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s

management:
  server:
    port: 9090
  endpoints:
    web:
      exposure:
        include: health, prometheus
  endpoint:
    health:
      probes:
        enabled: true
      show-details: when-authorized
  metrics:
    tags:
      application: ${spring.application.name}
```

### 모니터링 역할 분담

| 주체 | 도구 | 용도 |
|---|---|---|
| 백엔드 | CloudWatch + Prometheus + Grafana | 개발 단계 모니터링 |
| 인프라-네이티브 | Prometheus + Grafana | 전체 서비스 운영 |
| 인프라-네이티브 | CloudWatch | 솔루션 기능에 따라 선택적 사용 |

## 환경 설정

| 항목 | 내용 |
|---|---|
| 설정 주입 | `application-{profile}.yml` + SSM Parameter Store |
| 프로파일 | `staging`, `prod` (dev 없음) |
| SSM 경로 | `/prod/backend/{key}` / `/staging/backend/{key}` |
| 하드코딩 | 금지, 환경변수로 주입 |

### JVM 리소스 설정

- `-XX:MaxRAMPercentage` 사용 시 컨테이너 `limits.memory`를 충분히 설정 (OOMKilled 방지)
- app 서버 최소 메모리: **4GB**
