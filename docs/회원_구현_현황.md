# 회원 도메인 구현 현황

## 구현 완료

- 이메일 가입, 인증 메일 재전송·1회성 확인, 로그인·로그아웃, 원자적 Refresh Token 회전, 내 정보 조회
- 카카오·구글 OAuth2 로그인, 제공자 이메일 검증, OAuth 결과 교환, HttpOnly 1회성 추가정보 쿠키, 신규 USER 생성
- 프로필 수정, 비밀번호 변경 시 전 세션 무효화, 탈퇴 소프트 삭제
- 배송지 CRUD와 기본 배송지 단일성 유지
- 장인 입점 신청, 관리자 승인·반려, 4단계 심사 파이프라인, 완료 시 USER → ARTISAN 전환
- 설정, 최근 본 작품 기록·병합, 관심 장인 구독의 저장 모델과 API

## 도메인 경계

주문·찜·후기·최근 본 목록의 응답은 상품·결제 테이블을 읽는 조회 투영으로 준비되어 있다. 상품·결제 도메인의 엔티티와 실제 테이블이 아직 없으므로, 해당 목록은 두 도메인 구현 후 PostgreSQL 통합 시나리오로 검증한다.

## 운영 전제

운영 프로필은 JPA `validate`를 사용한다. 배포 전에 `member`, `artisan_profile`, `seller_application`, `recent_view`, `artisan_subscription`의 현재 ERD를 운영 PostgreSQL에 반영해야 한다. 이 변경에는 member 프로필·탈퇴 컬럼, 장인 심사 단계 컬럼, 관심 장인 구독 테이블이 포함된다.

## 검증

- 서비스·Redis·보안·MVC 회귀: 84건 통과
- OAuth 제공자와 PostgreSQL/Redis의 실제 네트워크 통합은 로컬 Docker 엔진 접근 문제로 별도 실행이 필요하다.
